---
title: "Schema Validation Recovery"
description: "Automatically recover from malformed tool arguments emitted by models."
---

Models sometimes send `"42"` when your schema expects `42`. Without handling, that throws and kills the whole run. kenpachi catches validation failures, tries to fix them, and only gives up after configurable retries.

<Tip>
This is on by default for every `defineTool` (`repairable: true`). You don't opt in — it just works.
</Tip>

---

## What happens step by step

1. **Validate** — arguments are checked with `schema.safeParse()`.
2. **Coerce** — simple fixes (e.g. `"6"` → `6`) are applied automatically.
3. **Retry or inform** — if still invalid, the formatted error is returned to the model as a tool error so it can try again with corrected args.

You'll see `tool_repair_attempt` events if you use `onEvent` or `stream()`.

---

## Example

```typescript
import { z } from "zod";
import { Agent, defineTool, createOpenAIProvider } from "kenpachi";

const multiply = defineTool({
  name: "multiply",
  description: "Multiplies two numbers",
  schema: z.object({
    a: z.number(),
    b: z.number(),
  }),
  async execute({ a, b }) {
    return { product: a * b };
  },
});

const agent = new Agent(
  createOpenAIProvider({ apiKey: process.env.OPENAI_API_KEY!, model: "gpt-4o" }),
  [multiply]
);

// Model might send { a: "6", b: "7" } — kenpachi coerces and succeeds.
const result = await agent.run("What is 6 times 7?");
console.log(result.text);
```

---

## Disable repair for a tool

Set `repairable: false` when bad args should fail immediately (e.g. handoffs, security-sensitive tools):

```typescript
defineTool({
  name: "delete_account",
  repairable: false,
  // ...
});
```

Configure max retries per run with `maxToolRepairAttempts` on `agent.run()`.
